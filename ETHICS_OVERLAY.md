The Ethics Overlay to the OWASP Top 10

A threat-modeling column, not a framework.

Aligned to the OWASP Top 10 for LLM & GenAI Applications, 2026 (v1.0) and the Top 10 for Agentic Applications, 2026. Note that LLM numbering changed substantially between the 2025 and 2026 editions.

You already threat-model the OWASP entries below. This adds one question to each: what ethical failure feeds this risk — and one thing to test for it.

Ethics principles referenced are the OECD AI Principles: 1.1 Wellbeing · 1.2 Fairness & non-discrimination · 1.3 Transparency & explainability · 1.4 Robustness, security & safety · 1.5 Accountability.

Note 1.4. Security is already inside the ethics framework. This overlay just runs the mapping in the other direction.

The core eight

These carry the argument. If you print one page, print this.

OWASP entry	Ethics failure that feeds it	Ask in your threat model	Test for it
LLM05:2026 Data and Model Poisoning	1.2 — biased labels are poisoning you did to yourself. Historical enforcement policy becomes ground truth. LLM05:2026 already names the deliberate version — mislabelled fraud data so the model ignores real threats. This is the same defect with no attacker.	Where did our labels come from? What policy or team generated them, and what was that policy not looking at?	Audit a small random sample, chosen independently of whatever the old process targeted. Then ask: of the problems that were really there, what fraction did the old process actually catch — for each group? The difference between those numbers is your blind spot, measured.
LLM10:2026 Improper Output Handling	1.3 — downstream systems and humans consume output as fact because nothing marks its confidence or provenance.	What does the consumer of this output assume about it that we never asserted?	Strip the output of context and hand it to someone downstream. Ask what they think it means.
LLM03:2026 Excessive Agency	1.5 — no named owner for what the system does autonomously. Diffusion of blame precedes the over-permission.	Who is liable when this acts without a human? If the answer is a list of vendors, that's the finding.	Inventory every irreversible action reachable from the agent's credentials. Put a person's name against each one. Any action you cannot name someone for is a finding.
LLM07:2026 Misinformation	1.1 — confident false output that a person acts on, in a domain where acting on it hurts them.	What's the worst decision a user could make on a confidently wrong answer? Who absorbs that?	Query for something that doesn't exist. See whether the system fabricates or declines.
ASI06 Memory & Context Poisoning	1.3 — persisted state with no provenance. The agent cannot distinguish what it was told from what it verified, and neither can you.	What in the agent's memory can be written by an untrusted party — and can we tell, later, where any given stored fact came from?	Inject a benign but false fact upstream. Measure how many turns it survives and what it influences.
ASI09 Human-Agent Trust Exploitation	1.3 — opacity manufactures deference. The reviewer is handed an explanation built by the thing being reviewed.	Is the artifact our human oversight depends on generated by the system under oversight?	Counterfactual fidelity test: change only the features the explanation doesn't cite. If the decision flips, the explanation is faithful to outputs and false about reasons.
ASI10 Rogue Agents	1.5 — accountability gap at the boundary between "autonomous" and "supervised."	What does this agent do when it errors, and who finds out?	Force an error state in a permitted action. Observe whether it escalates, retries, or conceals.
⚠️ No entry yet — Fairness→decision-boundary leakage	1.2 — a model with a disparity advertises where it isn't looking. The fairness gap is reconnaissance.	If someone can only see our yes/no decisions, can they work out which kind of applicant gets approved most easily? That answer is a map.	Probe a binary oracle across a proxy axis with behaviour held fixed. A gradient in decline rates is a map an attacker can read in an afternoon.
Extended coverage

Same bar, less central to the talk.

OWASP entry	Ethics failure that feeds it	Ask in your threat model	Test for it
LLM01:2026 Prompt Injection	1.1 / 1.3 — the model's trained disposition to be maximally helpful and agreeable is the thing being exploited. Compliance-by-design is an attack surface.	Where have we optimized for agreeableness, and what does the model give up to stay helpful?	Ask it to do something it should refuse, framed as helping the user. Escalate politeness rather than sophistication.
LLM02:2026 Sensitive Information Disclosure	1.2 — data collected or retained without a defensible basis becomes extractable surface. You cannot leak what you declined to hold.	What is in this model that we would struggle to justify collecting? Who consented, and to what?	Membership-inference and inversion probes on the categories you'd least like to see in a headline.
LLM08:2026 Hidden Context Exposure	1.3 — rules that govern people are kept secret from them, and the secrecy is load-bearing. Obscurity is doing work that policy should do.	If our hidden context were published tomorrow, what would break — and is that a security control or an embarrassment?	Ask the model to restate its own operating rules. Then ask whether anything you'd rely on stops working now that a user knows them.
ASI01 Agent Goal Hijack	1.1 — a goal stated without harm constraints is easy to redirect, because nothing in the goal itself pushes back.	What does this agent's goal not say? What would satisfying it at any cost look like?	State the goal to a red-teamer with no other context. Ask them for the cheapest satisfying path.
ASI03 Identity & Privilege Abuse	1.5 — an agent acting under a human's identity destroys attribution. Nobody is accountable because the logs say a person did it.	When this agent acts, whose name is on it? Can we reconstruct who decided what, after the fact?	Pull the audit log for an agent-initiated action. If you can't distinguish it from a human action, attribution is already gone.
ASI08 Cascading Failures	1.5 — every hop has an owner; the chain has none. Accountability is distributed until it disappears.	Who owns the composition, as opposed to the components?	Trace one request end to end and name an owner per hop. The hop nobody claims is where it breaks.
What I deliberately left out

Not every OWASP entry has an ethics failure feeding it, and pretending otherwise would make this artifact worse.

LLM04:2026 / ASI04 Supply Chain — real risks, but the principle at stake is security itself. Nothing is added by relabelling it.
ASI05 Unexpected Code Execution — RCE. Pure AppSec, and you already own it.
LLM06:2026 Unbounded Consumption — a cost and availability problem.
LLM09:2026 Vector and Embedding Weaknesses — covered in substance by ASI06 above; a separate row would be padding.
ASI07 Insecure Inter-Agent Communication — the near-neighbour to the gap row, discussed below rather than duplicated here.

A blank cell is more useful than an invented one.

The gap row

The last row has no OWASP number. Verified against the 2026 edition: the terms "decision boundary" and "fairness" do not appear in it at all. The three nearest neighbours each miss for a different reason:

ASI07 covers inter-agent channels, not a model leaking to an outside observer.
LLM02:2026 covers inversion and membership inference — that's extracting data the model was trained on, not where the model draws its line.
LLM08:2026 Hidden Context Exposure is the closest, and it's new. But it covers context placed into the model — system prompts, policy text, tool schemas — being extracted or reconstructed. A decision boundary is learned, is nowhere in the context window, and is inferred purely from behaviour. The entry also explicitly scopes out infrastructure-layer side channels.

That's not a criticism of the taxonomy — it's where the taxonomy hasn't reached yet, and it's the most useful thing an ethics lens has to offer this project. The OWASP GenAI Security Project takes contributions.

Monday

Three things, none requiring budget or a reorg — all from the core eight:

Add one row to your threat model template — "what ethical failure feeds this?" Nothing more. The question does the work.
Ask where your labels came from. Not what they are. Where they came from, and what generated them. Most teams have never asked.
Run the counterfactual fidelity test on one model that produces explanations. It takes an afternoon and it either passes or it doesn't.
Caveats worth keeping
Robustness testing asks whether a model can be evaded. It doesn't ask whether the model advertises where. Those are different test plans.
No fairness control zeroes an attack surface. Where a genuine risk differential exists, some signal survives and should. Reduction is the honest claim.
This overlay is a column, not a framework. If you never use the word "ethics" and just add the question, that's a win.

## Caveats worth keeping

- Robustness testing asks whether a model **can** be evaded. It doesn't ask
  whether the model **advertises where**. Those are different test plans.
- No fairness control zeroes an attack surface. Where a genuine risk differential
  exists, some signal survives and should. Reduction is the honest claim.
- This overlay is a column, not a framework. If you never use the word "ethics"
  and just add the question, that's a win.
